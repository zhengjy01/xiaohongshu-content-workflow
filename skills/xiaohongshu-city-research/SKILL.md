# 小红书城市研究

将城市选题做成可核验的研究，再按用户需要转成小红书内容。研究可信度高于标题冲击力；没有依据时宁可缩小结论，也不补造精确数字。

## 选择模式

- **选题雷达**：为近期线索、周报或候选选题检查来源、新鲜度、内容价值与优先级。
- **单题研究**：分析一座或多座城市、核验数字，或建立生活成本、人口、住房、教育、就业和产业模型。
- **小红书成稿**：在关键事实达到发布标准后，生成标题、正文、图卡或信息图提示词；素材不足时先研究或显著标出待核实项。

## 不可跳过的规则

1. 先定义时间、地域、行政层级、人群和指标口径；跨城市数据不可比时不要强排行。
2. 每个关键数字区分为官方原始数据、权威转述、派生值、估算值或尚未核实线索，并把来源放在相邻位置。
3. 媒体文章尽量回溯原始报告；“最近转载”不等于“最近发布”。涉及当前政策、数据或推荐时进行实时检索。
4. 派生值给计算式。估算值给假设、范围和局限；不能用“2026 最新”“精确排名”等措辞包装缺乏来源的模型结果。
5. 生活成本按每座城市独立建模，不迁移另一城市的数字或固定占比；先定义消费画像，再按当地价格逐项计算。
6. 将相关性、推测和因果分开。发现来源冲突时展示差异并解释采用哪个口径。
7. 文案不得偷偷删除研究中的限定词。事实层、解释层和创作表达层保持可区分。
8. **选题不得自行深入（⛔ 闸门 1，用户 2026-09-22 定稿）**：每日选题雷达产出后**必须停下等用户挑选题**，agent **不得自行选题**进入研究或成稿。用户挑中的条目标 `status: 已选题`，其余保留在池里供后续累积。没有任何"比较有把握所以先做着"的例外。

## 写作偏好

中文表达清楚、具体、不过度煽情。可在数据反差型、提问式、反常识型、纪录片型和拆解型之间轮换，避免反复用“没想到”“原来不错”等模板化开头。默认比例建议可用小红书竖版 3:4，但只有用户需要视觉方案时才展开。

署名/结尾以账号 slogan 为准；若涉及人设可用「🧠Light｜普通人城市选择指南」并落「帮你判断：这座城市值不值得去」，沿用账号风格时保留，否则不擅自添加。

## 权限边界

本 Skill 授权研究、计算、写作和视觉方案，不授权登录、抓取需 Cookie 的内容、点赞、评论、收藏或正式发布。任何账号操作、外部写入和发布都必须获得用户明确授权。

## 城市研究方法

### 先固定口径

搜索前明确研究问题、时间范围、空间范围、行政层级、人群口径、指标定义，以及需要事实描述、比较、解释还是估算。不同解释会实质改变结果时询问用户；否则采用最保守的合理解释并说明。

### 来源优先级

1. 国家及地方统计部门、政府公报、政策原文、部门新闻发布会；
2. 官方开放数据、权威研究机构、论文和带方法说明的行业报告；
3. 对原始材料有明确链接的权威媒体；
4. 平台、企业或民间数据库；
5. 自媒体、论坛和搜索摘要，仅作为线索入口。

关键结论尽量使用原始来源；跨来源核验指标名称、发布时间、统计期、单位和适用条件。网页发布日期与数据所属期分别记录。最近转载的旧公报不能进入“本周新资料”。

### 证据标签

| 标签 | 使用条件 | 表达要求 |
| --- | --- | --- |
| 官方原始数据 | 官方原文直接给出 | 写明机构、统计期、链接 |
| 权威转述 | 可靠机构或媒体转述原始材料 | 尽量补原文；说明为转述 |
| 派生值 | 可由列明的数据计算 | 展示公式、单位和舍入方式 |
| 估算值 | 依赖模型、抽样或假设 | 给范围、假设、敏感因素和局限 |
| 尚未核实 | 只有线索或口径不清 | 不进入标题、排行或定论 |

没有证据支持时，不生成精确人口、籍贯流向、租金或城市排名。改为说明可靠资料能支持什么、目前缺什么、需要怎样的数据才能计算。

### 可比性检查

- 行政层级与空间范围一致；
- 年份、月份及累计期一致；
- 常住、户籍、就业或参保人群一致；
- 名义价格、实际价格及是否含税费一致；
- 总量、人均、百分比和百分点没有混用；
- 单位已经统一；
- 政策适用对象和生效期限一致；
- 样本平台、房型、城区范围和统计方法一致。

不可比时拆表展示，或把结论降为定性观察。

### 派生计算

每项计算保留输入、公式和结果。例如：

```text
死亡/出生倍数 = 死亡人数 ÷ 出生人数
隐含均价 = 销售额 ÷ 销售面积
同比差 = 本期增速 - 对照期增速（百分点）
月均支出 = 年度支出 ÷ 12
```

检查除零、单位换算、累计期差异和四舍五入。由销售额与面积推得的均价只能描述整体结构，不能冒充楼盘价格指数。

### 城市生活成本模型

先定义画像，例如“当年普通单身上班族 P50、主城区合租或普通单间、不含房贷、养车、养娃、旅游及奢侈消费”。每座城市重新采集并说明：

- 住房：租金样本范围，加水电、燃气、网络和必要物业费；
- 饮食：按完整月份计算，不能只算工作日；
- 通勤：当地公交、地铁、骑行和偶尔打车的组合；
- 生活日用：洗护、纸品、衣物和必要网购；
- 娱乐社交：与画像相符的普通频率；
- 医疗：合理年度支出折算月均，不默认商业保险；
- 其他：通讯、理发、学习等明确项目。

输出项目值、区间、来源、计算式和总额。统一的是画像和方法，不是各城市的数字或占比。

### 选题评分

按新鲜度、可信度、城市相关性、数据张力、可视化性和受众价值定性或 1–5 分评分。推荐前三名时写排序原因；不要用旧资料或弱证据凑满数量。

### 发布前质量门

- 标题里的数字在正文和来源中都能定位；
- 统计期、发布日期、范围、单位和人群口径齐全；
- 派生值可复算，估算值有显著标注；
- 没把相关性写成因果；
- 没有从其他城市复制不适用的假设；
- 文案保留关键限制条件；
- 原始链接可用，或说明最后核验时间和替代来源；
- 结尾列出局限和仍待核实的问题。

## 素材挖掘（选题主动 / 被动来源）

账号：**Light｜普通人城市选择指南**（🧠 拆解城市资源/工作机会/薪资水平；🏙️ 商场·配套·便利度真实记录；💰 帮你判断「这座城市值不值得去」）。垂直不局限于数据榜单，含城市生活向观察。选题来源两条路，**默认每天**产生一份「城市研究选题雷达」供用户挑选。

### 主动来源（用户抛主题）

用户直接给一个想法/城市/疑问 → 直接进「选择模式」，评估数据可得性后做。可帮用户把一个模糊想法转成可做的问题（如「杭州」→「杭州哪个区租金贵 / 哪来外地人最多 / 一个月花多少」）。

### 被动来源（每日选题雷达·自动）

每天主动检索近期城市相关**热点数据**，产出一份候选选题清单，让用户从里面挑。规则：

- 数据源清单（按优先级）：国家/省市统计局与公报、统计年鉴、贝壳/链家/安居客（房价租价）、58 同城（租房）、城市 GDP/财政、人口与七普后续、结婚/生娃/抚养/养老数据、旅游/演唱会/漫展/养宠等民生榜单、新闻热榜上的城市话题。
- 检索范围：最近 1 周为主（数据新鲜），可用最近 1–3 月做背景。
- 产出：10–15 个候选选题，每个给「选题 + 数据反差/角度 + 痛点人群 + 可选题型 + 证据等级 + 一句话为什么值得做 + **来源原链接**」＋最值得做的 3 个写排序理由。数据拿不准标「待核实」，不编造。
- **选题铁律（用户定稿）：必须「痛点驱动、具体可感」**——打特定人群的具体痛点（收入焦虑/房租成本/存钱/通勤/选择困难/婚恋生育/落户门槛），能让人一眼对号入座（「在 X 城月薪 8000 能活吗」「预算 2000 在 X 城能住哪」「XX 到底选 A 还是 B」）。**禁止**宽泛抽象的「元问题/框架类」选题（如「XX 值不值得去」「城市怎么选」这类没人点），除非把它落到非常具体的痛点场景。

### 话题公式模板（痛点问法，从历史 62 篇归纳，直接套用）

- 收入/生存：`在X城月薪X能活吗`、`X城月薪多少才存得下钱`、`最存不下钱的城市 TOP`
- 房租/居住：`预算X在X城能住哪`、`X城哪个区租金贵`、`X城房租连涨`
- 选择/纠结点：`去X还是Y`（具体两城对比）、`拿到X薪资该选哪个城市`
- 归属/身份：`哪座城市的外地人最多`、`某省外省人最多`、`X城的外地人从哪里来最多`
- 婚恋生育：`哪座城市最多人结婚/生娃`、`X城哪个年龄段最难结婚`
- 门槛/机会：`X城落户/定居难不难`、`哪些城市工作机会×薪资性价比高`、`X城房价跌了还能上车吗`

### 标题检查

- 数字可由正文和来源定位；
- “最、第一、暴涨、消失”等词有足够证据；
- 没把估算写成普查或官方结论；
- 标题保留影响结论的范围和时间；
- 冲击力来自真实反差，而不是删除限定词。
