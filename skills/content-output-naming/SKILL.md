# 自媒体内容命名与归档

把 Obsidian 里的内容输出（`3️⃣ output/media/` 下各平台）按统一规则命名和归档，方便全局搜索、按时间回溯、按状态筛选。新建内容、给内容归类、决定是否再分一层系列文件夹时都按本规则执行。

## 目录结构

`3️⃣ output/media/` 下按平台分文件夹，已存在：`小红书/ 公众号/ 抖音/ 哔哩哔哩/ 知识星球/`。新增内容平台时在此**平级**加文件夹，不要用日期给文件夹命名（会建一堆空目录）。

结构约定：

```
3️⃣ output/media/<平台>/
├── _模板.md            # 内容模板（frontmatter + 正文骨架），新建内容复制它
└── <系列>/**/**        # 系列文件夹 → 单篇内容
```

## 内容文件命名（核心）

每篇内容 = 一个文件，命名格式固定为：

```
YYYY-MM-DD-关键词1-关键词2
```

示例：

```
2026-02-09-杭州买房-预算300w.md
2026-02-09-杭州vs成都-宜居对比.md
2026-09-05-新手避雷-副业.md
```

规则：

1. **日期放最前**，格式统一 `YYYY-MM-DD`（不要用 `2.9`、`2026/2/9` 等变体）。
2. **关键词用「-」连接**，用能重复命中的实词（如 `杭州买房`、`新手避雷`），不用「记录/笔记/未命名」等泛词。
3. **不把平台名写进文件名**——已在对应平台文件夹内，避免冗余。
4. **文件名不写内容状态**（草稿/已发布）——状态交给 frontmatter，避免文件名脏乱。

## 系列文件夹

内容一多，按「主题/系列」再分一层：平台文件夹 → 系列文件夹 → 单篇。

- 系列文件夹用**主题名**（如 `城市系列`、`避雷踩坑`、`攻略干货`、`长文`）。
- 散稿**先按日期平铺**在平台根或已有系列里，同一主题**攒到 ≥5 篇**再新建系列文件夹归进去。
- 不主动建空系列文件夹；确认会持续产出的主题才建。

## frontmatter 字段（内容统一用）

```yaml
---
title:
series:          # 所属系列名，如 城市系列
platform:        # 平台，如 小红书
status: 草稿     # 草稿 / 打磨中 / 待发布 / 已发布
create_date:     # YYYY-MM-DD
publish_date:    # YYYY-MM-DD
url:             # 发布链接
tags: []
---
```

- 状态用 `status` 字段统一管理，`DataView` 可按 `status` 一键筛选「草稿/打磨中/待发布/已发布」。
- 发布后把链接填进 `url` 即完成归档；不移动文件、不改文件名。

## 内容状态机（不建物理草稿箱）

一篇内容从生产到发布，在**原平台/系列文件夹内原地**推进状态，不搬文件：

```
灵感 → 草稿 → 打磨中 → 待发布 → 已发布
```

- 状态推进只改 frontmatter 的 `status` 字段，文件名与所在文件夹不变。
- **不建物理「草稿箱」文件夹**：否则会有文件夹 + frontmatter 两份状态，易冲突，且搬文件会断反向链接/DataView 查询。
- 想集中看所有未发布内容：用 `3️⃣ output/media/草稿箱.md`（DataView 活查询视图）汇总 `status != 已发布` 的稿子，结果等同草稿箱但不用移动任何文件。
- 还没定平台 / 只攒素材的原始内容，先进 Vault 顶层 `0️⃣ inbox` / `1️⃣ input`，定了平台再按本规则命名归档。

## 模板文件

每个平台根放一个 `_模板.md`（frontmatter + 选题背景/核心内容/封面配图/发布信息），新建内容直接复制模板再改。模板字段见上，正文骨架见 `小红书/_模板.md` 实例。

## 三条原则

1. **文件优先于文件夹**：散稿先按日期平铺命名单条，同类攒够再归系列文件夹。
2. **日期始终开头**，格式统一 `YYYY-MM-DD`。
3. **关键词用实词**，能重复命中，方便全局搜索。
